# Specs

Specs define command behavior and user-visible workflow contracts.

- `codex-plugin-support.md`: support Codex plugin consumption alongside Claude
  Code plugin support.
- `clarify.md`: resolve blocking ambiguity in an existing spec before
  `/to-plan`.
- `explore.md`: discuss rough needs, explore solution directions, and produce
  ready input for `/to-spec`.
- `grill-me.md`: review selected requirements and solution directions
  before `/to-spec`.
- `jkit.md`: provide the root help and routing entry for the jkit workflow.
- `map-init.md`: initialize repository agent maps.
- `map-init-dry-run.md`: preview `/map-init` scaffold changes without writing
  files.
- `map-repair.md`: repair existing agent maps from project base facts.
- `run.md`: execute an active plan goal loop to verified completion and update
  maps.
- `runtime-install.md`: runtime-specific install UX, npm package name, and
  bilingual README.
- `runtime-update-check.md`: non-blocking update notices for common jkit
  workflow commands.
- `to-done.md`: adaptive orchestration from intent to verified done.
- `to-plan.md`: convert reviewable specs into executable ExecPlans.
- `to-spec.md`: convert unclear or new behavior requests into reviewable specs.
